# Databricks Fundamentals — Retail Lakehouse

Build a retail lakehouse with Unity Catalog, managed volumes, and Bronze, Silver and Gold Delta tables. Practice data validation, deduplication, aggregation and troubleshooting.

## Run the lab

1. Use a Unity Catalog-enabled workspace with compatible compute and managed storage.
2. Import `notebooks/01_retail_lakehouse.ipynb` into a Databricks workspace folder. The `.py` file is an alternative Databricks source import of the same notebook.
3. Select serverless notebook compute for the default-storage path.
4. Set `CATALOG` in Cell 01. Set `CREATE_CATALOG=False` if using a pre-created catalog.
5. Run Cells 01–11 sequentially.
6. Review Catalog Explorer and query the fully qualified Gold table from SQL editor if a warehouse is available.
7. Run Cells 12–17 one failure/repair pair at a time. Failure flags default to False. Reset them afterwards.

All source data is synthetic and generated by Cell 04. No pip installation or external data download is required inside Databricks. Included JSON files are fallback fixtures; the notebook generates the same records itself.

## Reruns and limitations

The demonstration uses a full snapshot replacement for its own files and tables. Use only the isolated course schemas. Repeating the notebook preserves business totals, but changes ingestion timestamps and table versions. It is not append-history ingestion, CDC, production data-quality coverage, end-to-end transactional orchestration or a benchmark. External-table provisioning and enterprise permissions are conceptual in this first lesson.

No automatic cleanup is included: keep these objects for later lessons. Remove only dedicated lab objects through your normal workspace process when no longer needed. Do not drop a shared catalog.

Free Edition is serverless-only and subject to feature/usage restrictions and non-commercial-use terms. Review the [Free Edition limitations](https://docs.databricks.com/aws/en/getting-started/free-edition-limitations) when choosing an environment.
